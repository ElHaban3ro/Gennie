# Configuración

Propietario: kernel/config. `Config` contiene ruta DB y busy timeout; `Secrets` separado, sin Debug ni AppState; contiene la clave opcional de OpenRouter. Bootstrap consume Secrets al construir clientes futuros. No inventar credenciales. Prefijo GENNIE_. Precedencia: entorno de proceso > `.env` explícito del cwd > defaults. No modificar entorno global mediante unsafe set_var; fusionar valores en memoria. Exportado distinto al archivo genera aviso solo con nombre.

## Variables de proceso
- GENNIE_DATABASE_PATH obligatoria sin default: archivo SQLite, no vacío ni `:memory:`. Instalaciones nuevas usan data/gennie.sqlite3; el .env local conserva la ruta existente al renombrar el producto. Las herramientas CLI resuelven rutas relativas al cwd; el escritorio las resuelve respecto al directorio del `.env` explícito para conservar la DB del checkout aunque Flutter arranque desde `frontend`. Las rutas absolutas se conservan.
- GENNIE_OPENROUTER_API_KEY opcional: clave privada de OpenRouter, necesaria solo al clasificar; no se registra ni persiste en SQLite.
- GENNIE_DB_BUSY_TIMEOUT_MS default 500, entero 1..5000. Una conexión, sin parámetros de pool o HTTP.

.env fuera de Git. .env.example lista todas las variables y distingue obligatorias/defaults; test compara declaraciones y defaults. No sobrescribir .env existente. Falta de ruta falla temprano con nombre, no valor. Error de parseo no debe filtrar valores sensibles; cuando se añadan secretos sanitizar mensajes del parser también.

## Preferencias de app
Presence conserva `reduced_motion` y las tablas históricas de apariencia/visibilidad por compatibilidad de datos. La UI Flutter no representa la cara ni expone ajustes de presencia flotante. No modificar migraciones existentes ni borrar preferencias para retirar la interfaz.

El runner macOS en release, sin `GENNIE_ENV` ni `GENNIE_DATABASE_PATH`, entrega desde bootstrap una ruta explícita `~/Library/Application Support/Gennie/gennie.sqlite3`. El kernel mantiene la variable obligatoria para herramientas CLI. Desarrollo utiliza el `.env` existente. No se copia ni migra automáticamente la base del checkout al paquete release; abrir con una ruta explícita permite elegir la base existente.

Validar obligatorias, rangos, precedencia y sincronización ejemplo/declaraciones; reapertura del archivo demuestra persistencia. Ver testing y database para transacciones.

## Preferencias de transcripción
`transcription_preferences` pertenece a transcription: enabled=true; shortcut=Ctrl+Option+Space (parser handy-keys, capturado en UI); mode=hold (hold/toggle); bubble_seconds=15 (2..30, dato histórico sin globo visual); unload_seconds=600 (0..600, cero descarga inmediata; UI en minutos); microphone_name=None (entrada predeterminada del sistema). Entrada explícita identificada por nombre CPAL: ausente o ambiguo produce error, sin fallback silencioso. No guardar índice de enumeración. Migración 0002 añade selección y actualiza el tiempo existente a 600 por petición del usuario, sin cambiar 0001 ni los demás ajustes. Migración 0003 fija el default del globo en 15 s y cambia los valores guardados de 5 a 15; no distingue un 5 elegido explícitamente del antiguo default. Conserva otros tiempos y ajustes guardados. Aplicables después de commit sin reinicio, cancelando dictado en curso al cambiarlas. Modelo Q8_0 fijo, idioma es-ES en esta primera integración. No añadir valores a Config ni secretos. El GGUF reside en `~/Library/Application Support/AIModels/gguf`, compartido por usuario e independiente del checkout.

## Runtime de decisiones
`decision_preferences` pertenece a decisions: preload=true, unload_seconds=600 o NULL para mantener cargado; minutos enteros entre 1 y 120. Migración 0002 conserva 0001 y el diario. Precarga se aplica al siguiente arranque/conexión del Controller; el plazo tras el commit, desde la última petición terminada. Guardado propio para herramientas independientes de decisions; Presence no expone estos ajustes. El escritorio crea un Controller manual para consultar y cargar/liberar Laya desde la barra vertical; esa conexión omite la precarga de sesión y no modifica la preferencia guardada. [D-019](../decisions/laya-settings.md).

`apps/decisions` posee ~/Library/Application Support/soc/decisions/runtime.json: python y model, rutas absolutas existentes, sin defaults externos ni secretos, releídas al crear el hijo. El checkpoint configurado de Laya reside bajo `~/Library/Application Support/AIModels/huggingface/hub`; el entorno Python sigue siendo independiente. No añade variables GENNIE_ ni altera .env. El dictado siempre entrega el texto final a Codex. El runtime de Laya queda disponible para herramientas independientes, sin selección de destino en la UI. Ver [control](../decisions/control.md).

La versión D-017 permite adapter como ruta absoluta opcional de adaptación verificada por hashes. runtime-v2.json tiene prioridad para el binario nuevo; runtime.json se conserva para procesos antiguos. configure_laya --adapter escribe v2 por defecto. Una configuración/adaptación inválida falla; no se oculta con fallback. Ver [semántica](../decisions/semantic-control.md).

## Voz de salida de Gennie
`tts_preferences` pertenece a tts: enabled=true, voice=ef_dora (opciones ef_dora, em_alex, em_santa), speed_percent=100 (70..130) y unload_seconds=600 o NULL para mantener cargado. El plazo admite minutos enteros entre 1 y 120 y cuenta desde la última reproducción terminada. Migración 0002 conserva 0001 y los valores anteriores. Guardado independiente confirmado después del commit y aplicable sin reinicio; Probar voz usa los valores de pantalla sin guardar. El entorno Python sigue en `~/Library/Application Support/soc/tts`; la caché Hugging Face de Kokoro comparte `~/Library/Application Support/AIModels/huggingface` con otros proyectos. Falta de entorno/modelo produce error visible, sin sustitución. No hay secretos ni nuevas variables GENNIE_. [D-022](../decisions/tts.md).

## Conexión con Codex
La sesión ChatGPT pertenece a Codex CLI (`codex login`); Gennie no importa tokens en Config, Secrets, AppState ni SQLite. En macOS, preferir el CLI incluido con ChatGPT para acceder al catálogo de modelos vigente y usar el autónomo si falta. `llm_preferences` posee lectura, escritura, comandos y acciones locales booleanos (todos default true), modelo `gpt-6-luna` y esfuerzo `low` por defecto. Escritura requiere lectura; control de apps requiere comandos. Validar nombre de modelo y esfuerzo; comprobar disponibilidad en `model/list` sin sustitución silenciosa. Guardar desde el worker, confirmar tras commit y reconectar el hijo en la siguiente petición. El proceso usa un `CODEX_HOME` aislado con enlace al `auth.json` original cuando existe, sin heredar configuración global, plugins, apps ni MCP globales. Bootstrap inyecta únicamente el MCP local de Gennie mediante overrides de lanzamiento, con herramientas de módulos activos; ver [D-025](../decisions/assignments.md). La búsqueda web nativa se habilita siempre en modo live y no ofrece interruptor. Si la sesión global está en otro almacén y no hay archivo, la conexión debe fallar visiblemente. `gennie-llm` guarda solo el `thread_id` en `codex_conversation` para reanudar el mismo hilo. No añade variables GENNIE_ ni altera `.env`. Si la sesión falta o la reanudación falla, mostrar error y conservar el identificador. [D-021](../decisions/llm-conversation.md).

## Herramientas de desarrollo

El navegador propio usa `~/Library/Application Support/Gennie/browser/profile`, fijo y separado del perfil personal, de SQLite y de los navegadores descargados. `scripts/setup_browser.sh` prepara explícitamente el runtime Playwright 1.64.1 y enlaza el Node local (>=20) en `browser/runtime-1.64.1`; no usa `.env`, no crea preferencias ni instala al abrir la UI. El helper recibe las rutas y `PLAYWRIGHT_BROWSERS_PATH` solo en su entorno hijo. La distribución actual requiere esa preparación por usuario también para release. Herramientas MCP del navegador condicionadas a control de apps y comandos; apertura manual desde el botón independiente. Ver [D-026](../decisions/browser.md).

`./scripts/dev.sh` entrega rutas de biblioteca, helper y `.env` mediante dart-defines. No añade preferencias ni modifica `.env`. `--build-only` prepara Rust y paquetes sin abrir UI; `--generate` regenera FRB. Flutter debug puede abrir servicios temporales locales de depuración; el producto no abre HTTP entrante.

Al abrir Gennie se solicita automáticamente la conexión de Codex en segundo plano. Se verifica el inventario MCP del hilo antes de declarar Conectado; la primera intervención reutiliza la sesión. No hay mensaje de calentamiento ni inferencia. Falta de autenticación o fallo de descubrimiento producen error visible y reintento explícito con Conectar.

Capturas, PDF y descargas de Gennie Web pertenecen a `browser/artifacts` y persisten tras cerrar; directorio 0700, archivos 0600 y nombres generados. Upload requiere lectura de archivos activada y rutas explícitas elegidas para la tarea; vaciar/cancelar una selección no lee archivos. No añade preferencias ni variables de entorno. Ver D-026.

Las recetas web viven en `browser/plugins`, directorio 0700 y JSON 0600, con revisión y evidencia mínima por función. No añaden variables, preferencias, credenciales ni tablas. Sesión compartida y acceso únicamente bajo demanda; no solicitar login al guardar una receta o consultar contenido público. Ver [D-027](../decisions/web-plugins.md).

El constructor de plugins usa un workspace/CLI home por trabajo bajo Application Support/Gennie/plugins/builds, con hilo Codex propio y los ajustes de modelo/esfuerzo vigentes. Reutiliza el mecanismo de autenticación aislada existente sin copiar credenciales. No incorpora variables ni secretos nuevos; el presupuesto vive en el trabajo. Catálogo UI/MCP propio independiente de permisos de comandos; construir/ejecutar requiere control de apps y comandos. Ver [D-027](../decisions/web-plugins.md).

Proactivity carga GENNIE_OPENROUTER_API_KEY desde el .env explícito o el entorno, con precedencia del entorno. Su ausencia no impide arrancar. Se elige Jev u OpenAI Decisions por llamada, ambos mediante OpenRouter.
