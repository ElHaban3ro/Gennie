# D-028 — Plugins de servidores MCP externos

29 de octubre de 2026. Backend y gestión local Flutter integrados; verificación nativa parcial y matriz restante en el [plan de chats y agentes](../plans/gennie-chats-agentes.md). No sustituye el constructor web ni añade un ejecutor periódico.

## Propiedad y transporte

Plugins posee configuración, catálogo y permisos de conexiones MCP en `plugin_mcp_sources` (0006). LLM aporta `mcp_client`, un adaptador de protocolo sobre el app-server instalado, sin acceder a tablas de Plugins. Se reutiliza el arranque IPC del proveedor; el canal de herramientas omite account/read, model/list y turn/start, no enlaza auth.json y crea un hilo técnico efímero sin diario. No crea/reanuda conversaciones del usuario ni solicita inferencia.

Cada servidor usa un proceso app-server propio bajo `plugins/mcp/<id>`, stdio y permisos de herramientas nativas desactivados. Se admiten servidores stdio (comando/argumentos, carpeta opcional y nombres de variables) y Streamable HTTP (HTTPS; HTTP solo loopback; variable de bearer opcional). No importar configuración global ni pedir credenciales en el chat. No hay interfaz de OAuth ni servidor HTTP entrante del producto; una integración que necesite autorización interactiva adicional requiere ese diseño. El servidor stdio ejecuta código con permisos del usuario, sin sandbox del proceso: exige los cuatro permisos de Gennie. HTTP exige comandos/control habilitados según los ajustes actuales.

La interfaz usa mcpServerStatus/list y mcpServer/tool/call, contrastadas con [app-server](https://learn.chatgpt.com/docs/app-server) y el schema de Codex CLI 0.165.0-alpha.1.2. Configuración de transportes según [MCP en Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli). Una prueba local no certifica versiones futuras del CLI.

## Configuración, permisos y ejecución

Guardar no conecta: crea/reemplaza una especificación validada y deja deshabilitados servidor/herramientas. Conectar descubre sin ejecutar herramientas. Hasta veinte fuentes, catálogo de hasta mil herramientas y dos MiB; el exceso falla explícitamente. No recortar ni declarar vacío un catálogo incompleto. El inventario tiene un plazo total de treinta segundos y hasta veinte páginas; se detectan cursores repetidos e identidades duplicadas. Cada herramienta admite entre 1 y 720 segundos, reservando 180 segundos del presupuesto del host para arranque y metadatos. Nombres de variables, no valores, en campos de autenticación; argumentos son datos del comando elegido, sin interpretación de shell por el serializador.

Permisos por herramienta y habilitación explícita de fuente, separados de disponibilidad técnica. Un cambio de configuración limpia catálogo/permisos. Refrescar conserva permisos solo para definiciones idénticas; herramientas nuevas o modificadas no los heredan. Las revisiones evitan guardar/ejecutar sobre configuraciones antiguas. Una petición obsoleta no recrea el cliente anterior. Una conexión ocupada devuelve busy con executed=false, sin encolar la acción. Eliminar deja una identidad/revisión de reserva para evitar reutilización insegura; recrear inicia permisos vacíos.

La validación JSON Schema se ejecuta fuera del lock SQLite, antes de llamar: referencias locales, objetos/listas, alternativas y restricciones; resolución externa de archivos/red desactivada. Esquema no admitido o inválido impide habilitar/ejecutar esa herramienta, sin tratarlo como validación exitosa. Se acotan tamaño de patrón y backtracking; esto no constituye aislamiento ni una garantía de tiempo total para cualquier esquema. Errores de entrada devuelven rutas/razones estructurales sin texto libre del validador que incluya valores de argumentos.

Antes del efecto se refresca el contrato y comprueba revisión/permiso vigente. Las herramientas `plugin_mcp_catalog` y `plugin_mcp_run` permiten uso desde chat sin Encargo; no permiten que el modelo cree fuentes o conceda permisos. Los metadatos y resultados externos son datos no confiables. El bot pide datos requeridos/destinatarios ambiguos y conserva la autorización concreta del usuario. Un permiso técnico no autoriza cualquier efecto.

El cliente de Gennie envía una sola RPC por llamada y, ante pérdida de canal, cierra su proceso sin reenviarla; el resultado se presenta como incierto. Un error informado por la herramienta tampoco garantiza ausencia de efectos. No hay promesa de ejecución exactamente una vez en servicios externos ni compensación de efectos. La revocación cierra clientes propios; una acción ya enviada puede haberse aplicado. La migración 0007 registra el intento antes de enviar la llamada. Un error de transporte, un error informado por la herramienta o un fallo de confirmar el resultado conserva el bloqueo de esa fuente/herramienta, aunque cambien argumentos, ficha, permisos o configuración. Al reiniciar, reservas pendientes pasan a uncertain sin reenvío. La eliminación exige resolver los intentos pendientes. La ficha permite registrar applied o not_applied solo después de la comprobación humana; no preselecciona opción ni ejecuta al guardar. La revisión cambia la revisión de la fuente para rechazar solicitudes anteriores y el catálogo presenta la última revisión de cada herramienta, hasta veinte entradas recientes. El bot no dispone de una operación de revisión. El bloqueo durable de funciones web continúa en D-044; no se añade una equivalencia universal entre fuentes/herramientas como requisito. El caso semántico de ruta alternativa sigue pendiente de la campaña preparada. D-045 propaga contexto/EOF/cierre por consumidor y D-047 cancela el turno propio; cerrar un consumidor no prueba que un efecto externo ya enviado se haya deshecho.

Stop cierra la entrada de operaciones, cancela los clientes y espera también las escrituras finales del diario antes de unir lectores/cerrar SQLite; no arranca conexiones al iniciar la app ni por listar datos guardados. El SDK administra sus transportes; no se detienen navegadores o procesos ajenos. Elicitaciones/solicitudes de aprobación que el canal no implementa fallan explícitamente.

## Datos y evidencia del chat

Se persisten especificación, revisiones, catálogo, permisos, fecha UTC de observación y metadatos del intento (ID AUTOINCREMENT, fuente/herramienta, nombre y revisión al ejecutar, estado, razón fija y revisión humana). No argumentos, resultados, contenido de herramientas ni errores libres. Datos nuevos comparten la única conexión SQLite y migraciones 0001..0006 de Plugins siguen intactas. El índice parcial permite solo una reserva pendiente por fuente/herramienta; reserva y comprobación de permiso/revisión confirman juntas. La red ocurre fuera de SQLite. Un fallo de reserva impide enviar; un fallo del commit final conserva la reserva y comunica incertidumbre. Mutaciones y lectura resultante confirman juntas; los contadores de revisión cambian después del commit.

La evidencia conversacional normaliza una llamada de proxy como servidor `mcp:<id>` y herramienta remota real. Nombre legible solo del resultado local con identidad coincidente; no se copian cuerpos. Los estados de dominio distinguen éxito, rechazo previo, fallo informado e incertidumbre. FRB sigue usando plugin_request JSON, sin cambiar el DTO generado. El catálogo entregado al modelo excluye programa, argumentos, carpeta, URL y nombres de variables; la ficha humana conserva esa configuración. El proxy retira _meta de los sobres de protocolo antes de entregarlos al modelo, conservando las claves de usuario de structuredContent. D-043 conserva isError y bloques MCP nativos de texto/imágenes/audio/recursos, separados de source y structuredContent, sin duplicar binarios en el JSON local. Sus pruebas y límites permanecen en [contenido nativo](native-mcp-content.md); los enlaces a recursos no se descargan automáticamente. Un fallo de leer fuentes MCP no retira el catálogo web ni los trabajos. La evidencia usa el código result_uncertain ya admitido por presence para indicar que el intento requirió revisión, sin alterar migraciones históricas ni guardar datos del resultado.

## Gestión visual

Plugins mantiene AppSidebar, cabecera y marcos compartidos. Nuevo plugin conserva el constructor web y ofrece conectar un servidor MCP existente. La ficha permite editar, descubrir, desconectar, eliminar, elegir herramientas, habilitar y guardar permisos explícitamente. No se conecta al guardar o listar. Edición y opciones avanzadas conservan borrador, validación junto al campo, foco/desplazamiento al primer error y acciones visibles al mínimo de ventana. Variables de autenticación se introducen por nombre, no por valor.

La prueba reutiliza campos tipados cuando el esquema admite esa proyección y ofrece JSON avanzado; las estructuras complejas usan JSON etiquetado con acceso al esquema completo. Rust siempre valida el contrato completo. El envío pendiente bloquea una segunda llamada y cambios de selección/permisos; Desconectar puede cerrar el canal durante una ejecución. Los resultados de pruebas manuales permanecen transitorios, sin guardarse en SQLite. La evidencia del chat abre la fuente mediante su identidad mcp:<id>, sin confundirla con un plugin web del mismo nombre. Resultados pendientes muestra páginas de cincuenta intentos, con total y carga de siguientes; incluye herramientas retiradas del catálogo. El diálogo conserva título/acciones visibles, cuerpo desplazable, selección ante error y ausencia de opción predeterminada. Confirmar no envía otra llamada. La revisión conserva el borrador de permisos y de argumentos. Los cambios de actividad refrescan solo metadatos; las respuestas tardías no restauran intentos ya revisados. En ancho mínimo se omite el icono grande de la ficha para dar espacio al nombre; la barra general no cambia.
