## Ejecutor y aislamiento

`scripts/probes/assignment_evaluation.py` prepara un plan sellado con SHA-256 de alcance, corpus, fuentes relevantes y binarios. Un cambio requiere otro plan; el identificador de ejecución no sustituye la aprobación humana. El test Rust optativo usa el propietario real de Assignments con SQLite en memoria, herramientas reales de lectura/propuesta y documentos ficticios normalizados por su validador. Las identidades reproducibles se insertan solo en ese fixture, sin alterar triggers ni migraciones. El codec agrupado rechaza campos desconocidos y comprueba ida/vuelta exacta.

Cada celda del bot abre un perfil Codex nuevo y una sesión efímera. Solo expone `assignments_review_get` y `assignments_propose`; no expone aplicación, edición, archivos, comandos, búsqueda web o aplicaciones. El modo `protocol` no enlaza credenciales, consulta cuenta/modelos ni inicia turnos. El modo `live` necesita la sesión ChatGPT existente, enlazada únicamente en su perfil temporal. El servidor MCP usa transporte local privado, sin HTTP entrante. El worker espera o termina sus hijos propios y retira el perfil; no inicia la UI ni abre la DB personal.

Bot con guía es una variante separada: requiere configuración y consentimiento del plan, usa el controlador existente y no sustituye una guía ausente por bot solo. Una llamada fallida permanece registrada, sin repetirse. El piloto preparado no incluye esa variante ni consultas OpenRouter.
