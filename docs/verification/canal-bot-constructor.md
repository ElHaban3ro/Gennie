# Canal del bot al constructor

El bot usa `plugin_build_jobs` con `action=message` para guardar respuestas y correcciones de la misma conversación, arquitecto, época e hilo que originaron el trabajo. La clave de solicitud evita duplicados. Si el constructor espera al usuario, el mensaje reencola el trabajo; si está activo, el host intenta introducirlo en el turno mediante `turn/steer` y el identificador del turno activo. Si el proveedor rechaza el envío, queda pendiente para el siguiente turno. Durante el envío se frenan nuevas llamadas a herramientas y la promoción espera a que no queden mensajes pendientes. Una operación ya iniciada puede terminar.

La bandeja distingue pendiente, en envío, aceptado o incluido en un turno completado, e incierto. La aceptación del proveedor no confirma que el constructor haya aplicado la corrección. Si se pierde la confirmación, el trabajo se interrumpe sin reenvío automático. En Plugins la persona puede revisar el texto, indicar que fue recibido o elegir reenviarlo al reanudar; la revisión no ejecuta la instrucción ni declara que se haya aplicado.

## Diagnóstico del navegador y nueva comprobación — 2026-11-09

El cierre intermitente se reprodujo con una sonda aislada que abre dos ámbitos reales de Chromium y cierra el worker. Con el límite anterior, este salió con código 1. Instrumentación temporal mostró dos ejecuciones de `context.close()` que completaron correctamente en aproximadamente 10,8 segundos: el límite del worker era 3,5 segundos y el de Rust cinco segundos. Se amplió el cierre cooperativo a 30 segundos en el worker y el límite de espera del host a 35 segundos. Después pasaron tres repeticiones de la sonda enfocada. El límite sigue siendo acotado y una falla de cierre sigue comunicándose; no se afirma que todos los fallos posibles de Chromium estén resueltos.

En una reproducción distinta, el constructor guardó una función `transport=http` sobre una página HTML. El ejecutor HTTP exige JSON, por lo que `verify` devolvió `site_changed` y el diario conservó el intento como incierto. La herramienta contextual `plugin_candidate` reemplazaba la descripción original y omitía esa diferencia de transportes. Su descripción ahora explica que `http` requiere JSON y que `page` extrae HTML con selectores. En una corrida posterior el constructor eligió `page` y la verificación del candidato devolvió `Catálogo públicoAZUL-42` con `reported_success`.

La web sintética original atendía conexiones secuencialmente y leía la petición con una sola llamada a `read`; se observaron conexiones vacías. Para evitar que sus esperas y lecturas parciales afecten las conclusiones, la sonda se cambió para atender conexiones en paralelo, leer la primera línea completa y desactivar la caché. Esto corrige un defecto de la fixture, pero no prueba por sí solo que explicara todas las lecturas contradictorias anteriores.

Con la fixture antigua, una ejecución posterior a la aclaración del transporte entregó ambas correcciones y publicó el plugin, pero la ejecución independiente devolvió contenido privado, por lo que la prueba falló. Con la fixture corregida, otra corrida creó el plugin y accedió a `/public`, pero el bot no transmitió la segunda corrección: afirmó que la herramienta no estaba disponible. No se considera validado el flujo completo por esas ejecuciones. Se conserva la verificación de efectos inciertos; no se autoriza un reenvío automático ni se elimina la revisión humana.

Con el servidor sintético concurrente y sin caché, el contrato de transportes actualizado y los plazos de cierre coordinados, la prueba completa `python3 scripts/probes/chat_builder_feedback.py` terminó satisfactoriamente en 106,16 s de ejecución de la prueba. El bot creó el trabajo, el constructor pidió intervención, el bot transmitió las dos correcciones y ambas se confirmaron en orden. El constructor publicó el plugin y una ejecución independiente de la función publicada devolvió `AZUL-42`; el backend y su navegador temporal cerraron sin el error anterior. Se utilizó el backend real del chat con bot y constructor Codex reales, no se automatizó la ventana Flutter. El ensayo usa datos, cuenta web y perfil sintéticos; el acceso a Codex utiliza una copia temporal de la sesión autorizada.

Este resultado verifica esa muestra; no demuestra que hayan desaparecido todas las causas de resultados inciertos ni el fallo intermitente previo de selección de herramientas. La sonda de cierre enfocada `scripts/probes/browser_close_probe.mjs` conserva la reproducción de dos ámbitos del worker y pasó tres ejecuciones después del cambio. La medición de 10,8 segundos es la duración observada en dos cierres reales de Chromium, no un plazo garantizado para todos los entornos.
