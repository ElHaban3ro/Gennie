# Investigación de fallos de lectura web — 9 de noviembre de 2026

## Caso de Gmail

El intento histórico de detalle se ejecutó como `program`: navegó a la conversación y esperó `main h2`. En la sesión Gmail real observada previamente no había elemento `main`, pero sí elementos `[role="main"]` y un título bajo ese rol. El historial registró timeout en fase de lectura y tres invocaciones del bloque; no conserva el estado anterior del mensaje ni permite asegurar si cambió. La búsqueda y paginación son una función diferente, y ya se habían comprobado con dos páginas reales. Eso no comprueba la lectura del detalle.

La prueba optativa `gmail_detail_selector_timeout_preserves_uncertain_navigation` usa el ejecutor de recetas, Chromium/Patchright real con solicitudes interceptadas, Controller y SQLite temporales. Una página ficticia representa el DOM observado y cuenta navegaciones. El selector antiguo agota el plazo tras una navegación, registra resultado incierto y bloquea otra invocación; el selector con rol obtiene el texto. El runtime actual invoca el callback una sola vez. Esta prueba demuestra la cadena técnica, no que una navegación de Gmail conserve el estado sin leer ni que el mensaje histórico permaneciera intacto.

## Límites y resultado

Seguimiento: una repetición instrumentada de la prueba pública identificó `result_type_mismatch` en fase `execute`; ambos valores se descartaban por las restricciones del diario. La migración 0004 conserva esos valores y la interfaz los explica. La prueba no terminó correctamente y no autoriza inferir que el programa no tuvo efectos. Un fallo previo a obtener el contexto devuelve ahora una categoría fija y `executed=false`; la prueba Node/SQLite `node_recovers_after_context_failure_without_review` comprueba una llamada fallida y una llamada posterior correcta sin revisión. No demuestra que el constructor decida por sí mismo la segunda llamada.

Una nueva ejecución de `real_builder_recovers_a_failed_controlled_observation`, sin proporcionar el selector correcto en la consigna, pasó con Codex y Chromium reales sobre la web local ficticia: tras la observación fallida el constructor descubrió un selector y verificó el candidato sin revisión humana. Una repetición posterior de la web pública continuó en `waiting_user`, ahora con `result_type_mismatch` y `execute` conservados y explicados. Esto demuestra recuperación de observación controlada, no recuperación de escrituras cuyo efecto es incierto ni lectura completa de Gmail.

Seguimiento Gmail por petición del usuario: `gmail_print` utiliza la vista de impresión de la sesión del navegador de Gennie, sin API ni credenciales nuevas. La prueba optativa `real_gmail_print_reads_without_marking_unread` ejecutó la receta, Controller y diario temporal contra una conversación real que estaba sin leer; obtuvo texto con el asunto, recargó la bandeja y comprobó que seguía sin leer, con cero revisiones pendientes. No guardó ni imprimió el contenido. La prueba aislada `gmail_print_failed_read_recovers_and_does_not_load_mail_resources` comprobó fallo 403 sin bloqueo, recuperación y extracción sin ejecutar scripts ni descargar recursos. Una sola conversación no acredita la cobertura completa de todos los formatos, adjuntos, cuentas o cambios futuros de Gmail; el intento histórico continúa incierto.

Seguimiento en la conversación real: por petición expresa se cerró el intento histórico como `unknown`, sin afirmar si tuvo efectos; el programa de esa función quedó en cuarentena. Tras reanudar, el constructor interpretó inicialmente ese cierre como revisión pendiente y el bot volvió a pedirla: se corrigió la comunicación del estado actual y se reanudó el trabajo. La lectura segura y la consulta de bandeja se verificaron. El constructor recorrió 18 páginas antes de recibir una instrucción para detenerse; después se le pidió publicar solo las dos lecturas, dejando archivo pendiente. Publicó ese plugin parcial. En el mismo chat el bot ejecutó consultar_bandeja, leer_conversacion y consultar_bandeja: la traza confirmó la misma identidad en ambas listas, `no_leida=true` antes y después, texto no vacío y tres resultados correctos, sin pendientes. No se imprimió contenido. La prueba final no pidió confirmación, pero el recorrido completo sí necesitó las correcciones indicadas y no demuestra autonomía completa desde el primer intento. La lectura no incluye adjuntos ni acredita archivo.

Si ya está archivada no pulsa de nuevo; si no puede verificar el resultado conserva la incertidumbre. Una primera prueba real de la promoción no leída «4K all day» quedó incierta; consultas posteriores constataron que seguía en Recibidos y sin leer. Es evidencia para una conversación y esta sesión de Gmail, no para todas las cuentas o variaciones de la interfaz.

El diario registró éxito, pero la primera petición necesitó intervención: falta exponer y verificar el indicador de importancia antes de afirmar autonomía para esa condición.

Esta prueba cubre una conversación y no garantiza todas las variantes de la interfaz de Gmail.

La prueba no acredita el comportamiento con todas las bandejas ni una clasificación universal de importancia o publicidad.
